 Project Introduction  :  Performance Livestock Analytical Platform (PLAP) 
 
Performance Livestock Analytical Platform (PLAP)  is a data processing pipeline designed to handle large-scale livestock data efficiently. The project leverages AWS services like S3, Glue, Lambda, EMR, and Athena, along with PySpark, to transform and analyze data for business insights. The platform ensures data integrity, transformation, and optimization, supporting data analysts and scientists in making informed decisions.  

---

 Project Flow  

 Data Processing Layers:  

1. Raw Zone/Layer (L1) – Data Ingestion  
   - Source: MySQL  
   - The Data Ingestion team loads data into an S3 bucket while performing basic data sanitization and null validation to maintain data quality.  
   - Data is stored in a structured directory within the S3 bucket.  

2. Curated Zone/Layer (L2) – Data Processing  
   - The Data Engineering Team processes the data using PySpark.  
   - The transformed data is stored in a target S3 bucket for further analysis.  
   - On-Prem Hive queries were migrated to PySpark jobs on AWS EMR.  
   - Athena queries were optimized using partitioning strategies to enhance performance.  
   - Conducted Liquid Risk Analysis to assess the financial impact of asset liquidity.  

3. Consumption Zone (L3) – Data Utilization  
   - Data analysts and scientists utilize the curated data for business intelligence.  
   - Data is stored in Parquet format, making it efficient for querying and reporting.  
   - Insights are presented through dashboards for decision-making.

For the Performance Livestock Analytical Platform (PLAP) project, the Data Processing Layer (L2) can be designed using the provided tech stack (PySpark, Athena, SQL, IntelliJ IDE, GitHub, Amazon S3, AWS Lambda, AWS EMR). Below is a detailed explanation of how the data processing layer can be implemented:

---

 Data Processing Layer (L2) for PLAP

The Data Processing Layer is responsible for transforming raw data ingested from the Data Ingestion Layer (L1) into a structured and meaningful format. This layer applies business logic, performs data transformations, and prepares the data for storage in the target S3 bucket for further analysis and reporting.

---

 Tech Stack for Data Processing Layer
1. PySpark: For distributed data processing and transformations.
2. AWS EMR (Elastic MapReduce): To run PySpark jobs on a managed Hadoop cluster.
3. Amazon S3: For storing raw and processed data.
4. Athena: For querying processed data directly from S3 using SQL.
5. AWS Lambda: For orchestrating and automating data processing workflows.
6. SQL: For querying and analyzing data.
7. IntelliJ IDE: For developing and debugging PySpark and SQL scripts.
8. GitHub: For version control and collaboration.

---

 Steps in the Data Processing Layer

 1. Data Ingestion from L1
- Raw data is ingested into Amazon S3 from the Data Ingestion Layer (L1).
- Data is stored in a raw format (e.g., CSV, JSON, or Avro) in an S3 bucket (e.g., `s3://plap-raw-data/`).

 2. Data Transformation with PySpark
- PySpark jobs are used to read raw data from S3, apply transformations, and write the processed data back to S3.
- Transformations include:
  - Data Cleaning: Handling missing values, removing duplicates, and standardizing formats.
  - Data Enrichment: Adding derived fields (e.g., calculating livestock growth rates).
  - Data Aggregation: Summarizing data (e.g., average weight gain per livestock category).
  - Data Partitioning: Partitioning data by relevant fields (e.g., date, region) for efficient querying.

```python
from pyspark.sql import SparkSession
from pyspark.sql.functions import col, when

 Initialize Spark Session
spark = SparkSession.builder \
    .appName("PLAP Data Processing") \
    .getOrCreate()

 Read raw data from S3
raw_data = spark.read.format("csv").option("header", "true").load("s3://plap-raw-data/")

 Perform transformations
cleaned_data = raw_data.filter(col("weight").isNotNull())   Remove rows with NULL weight
enriched_data = cleaned_data.withColumn("growth_rate", col("current_weight") - col("initial_weight"))
partitioned_data = enriched_data.repartition("region")   Partition by region

 Write processed data to S3 in Parquet format
partitioned_data.write.mode("overwrite").parquet("s3://plap-processed-data/")
```

 3. Orchestration with AWS Lambda
- AWS Lambda functions are used to trigger PySpark jobs on AWS EMR when new data is ingested into S3.
- Lambda can also handle error handling, retries, and notifications.

 4. Querying Processed Data with Athena
- Processed data stored in S3 (in Parquet format) is queried using Amazon Athena.
- Athena allows analysts to run SQL queries directly on the data in S3 without needing to load it into a database.

```sql
-- Example Athena Query
SELECT region, AVG(growth_rate) AS avg_growth_rate
FROM plap_processed_data
GROUP BY region;
```

 5. Version Control and Collaboration with GitHub
- PySpark scripts, SQL queries, and Lambda functions are version-controlled using GitHub.
- Team members collaborate on code development and review changes through pull requests.

 6. Development and Debugging with IntelliJ IDE
- PySpark and SQL scripts are developed and debugged using IntelliJ IDE with PySpark and SQL plugins.
- IntelliJ IDE provides a seamless development experience with features like code completion, debugging, and integration with GitHub.

---

 Workflow of the Data Processing Layer
1. Trigger: New data is ingested into the raw S3 bucket (`s3://plap-raw-data/`).
2. Lambda Function: A Lambda function is triggered to start the PySpark job on AWS EMR.
3. PySpark Job: The PySpark job reads raw data, applies transformations, and writes processed data to the target S3 bucket (`s3://plap-processed-data/`).
4. Athena Query: Analysts query the processed data using Athena for reporting and analysis.
5. Version Control: All code changes are pushed to GitHub for collaboration and version control.

---

 Key Features of the Data Processing Layer
- Scalability: AWS EMR and PySpark enable distributed processing of large datasets.
- Cost-Effectiveness: Data is stored in S3, and Athena allows querying without the need for a dedicated database.
- Automation: AWS Lambda automates the triggering of data processing workflows.
- Efficiency: Partitioning and Parquet format optimize query performance and reduce costs.
